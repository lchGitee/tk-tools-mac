TikTok 直播工作台 · 使用说明书

单端直播（手机开播 → 软件接管推流）｜ 绝对真实数据 ｜ 一卡一机授权

一、软件简介

本软件是一款 TikTok 直播工具：手机开播（Device camera）→ 软件实时抓取本场直播的当场推流码 → 手机断网/飞行 → 软件用当场新码推流（视频素材代替摄像头，GPU 编码）→ 观众看到的是软件画面 → 手动下播手机 → 单端直播达成。

核心原则：绝不绕过手机、绝不用旧推流码、绝不建假新房间——每一场都用手机当场开播生成的新码。

二、快速开始（第一次使用）

① 激活软件：打开软件 → 将机器码发给签发方 → 粘贴本机专属授权码 → 点「激活」。之后直接进。
② 添加账号：主界面点「添加账号」→ 输入账号名 → 自动打开 TikTok 登录页 → 手机/账号登录 → 保存 Cookie。
③ 添加节点：点「代理设置 / 保存节点」→ 粘贴你的 vless:// 节点链接 → 保存 → 重启软件（内置 xray 自动起本地代理 10888）。
④ 配置签名服务（可选，推流帧签名用）：填入 RapidAPI 签名服务的 baseUrl / key / license_id。

三、直播流程（核心操作，按顺序）

  1. 手机打开 TikTok → 点开播（Device camera 模式），保持网络连接；
  2. 软件主界面点「重新获取推流码」——必须在断网前抓，当场新码（每场都变，不能复用旧码）；
  3. 确认软件已拿到本场推流码（状态变绿/日志显示成功）；
  4. 手机断网 / 飞行模式（不要点结束直播）；
  5. 软件点「开始内置推流」→ 软件会立即试探 + 若 duplicate 自动重试（等平台释放手机推流权，一般 30~60 秒）→ 观众看到软件画面（视频素材）；
  6. 直播结束：手动在手机端下播（恢复网络后下播，或按手机端提示操作）；
  7. 软件检测到下播会自动停止推流、清空本场数据。

注意：手机断网后不要点「结束直播/End」；断网期间别让手机自动重连太久，以免手机推流权抢占回来。若观众端显示黑屏几秒才下播，是平台释放推流的正常过程。

四、实时监控（实时动态）

① 开启监控：点账号卡片上的「开启监控」→ 弹出小电视窗口（观众端视角）+ 实时动态面板。
② 实时动态：显示真实数据——在线人数 / 点赞 / 礼物 / 关注 / 进场 / 评论，全部来自观众页实时解析，绝无虚拟数据。开播时重新记录，下播即清零。
③ 风险告警：检测到平台限流/限制文案、直播间异常时自动提示（例如 "LIVE visibility restricted / reproduced content"）。
④ 自动回复 / 智能回复：只在有人点赞、送礼物、@ 主播、命中自定义关键词时自动回复（主播不主动发言）。话术可在「智能回复」弹窗中修改。
  • 「打开直播间」：在新窗口打开观众页（点一次只开一个，重复点聚焦已开的窗口）；
  • 「观众链接」：复制观众端链接；
  • 下播后实时动态数据清零，重新开播再重新记录。

五、画面与素材

  • 「选择视频」：任意选择一个视频文件作为推流素材（支持 mp4 等）；
  • 「画面编辑」：素材图层 / 预览编辑（选择视频后同步到画面编辑，两者互通）；
  • 推流循环：按素材原始时长循环——30 分钟素材播 30 分钟后自动从头循环；不是固定时间重推；
  • 编码：优先 NVIDIA GPU（h264_nvenc）硬编码，无 NVIDIA 时回退 CPU（libx264）——建议直播电脑带 NVIDIA 显卡。

六、签名服务（帧签名推流）

TikTok 推流需要帧签名（SEI）。软件默认使用 RapidAPI 签名服务（tiktok-live-studio-api-signer）为每帧打签名，配置：

  • baseUrl：https://tiktok-live-studio-api-signer1.p.rapidapi.com/
  • apiKey / license_id：你在 RapidAPI 购买的订阅密钥；
  • 保存后自动生效；签名服务异常时推流会被服务器拒（invalid_sign / 握手失败等）。

七、节点 / 代理（内置 xray）

添加节点：代理设置里粘贴节点链接（支持 vless://、vmess://、socks5://）→ 保存 → 重启软件生效。
工作原理：软件内置 xray 内核（无需桌面 v2/v2rayN），起本地 SOCKS5 代理 127.0.0.1:10888，小电视 / 监控 / 后台页 / API 全部走节点；推流走本机隧道（RTMP 也走代理）。
  • 换电脑：只需把节点链接重新粘贴保存即可正常使用（节点本身要有效、能连）；
  • 节点测试失败常见原因：节点服务器 TLS 握手失败（SSL HANDSHAKE_FAILURE）→ 多为 节点串参数（sni= / pbk=）与服务器不一致或节点已失效，请换有效节点或用 v2 客户端导入同节点串验证；
  • 无节点时软件直连（推流本来需要可直连的网络环境，否则必须配节点）。

八、卡密授权

  • 打开软件先显示激活界面，输入有效卡密才能使用；
  • 授权永久有效、绑定指定机器：授权码只对签发时指定的机器码有效，其他电脑不能激活；
  • 软件根据硬件信息生成机器码；更换硬件或机器码发生变化时，需要重新签发授权；
  • 授权内容由签发方私钥签名，软件使用公钥验证签名，每次启动检查机器码是否匹配。

九、常见问题（FAQ）

问题解决
节点不可用 / 无法连接先测节点服务器是否在线（TCP 通但 TLS 握手失败=节点串参数/服务器问题），换有效节点；确认已保存并重启软件。
推流失败 duplicate手机推流权未释放：点推流后软件自动重试，等待 30~60 秒；确保手机已断网。
推流握手失败（handshake）代理/网络不通：确认节点可用、签名服务正常；看运行日志（菜单→查看运行日志）。
实时动态没数据确认已开启监控且小电视窗口正常加载观众页；观众端有互动才会记录（点赞/进场/评论/礼物）。
平台限流提示多为推流素材被判定「非原创/复制内容」：软件会提示，消除限制需换素材策略（真人出镜等），必要时申诉。
礼物数量不增加礼物消息渲染在观众页特定层，软件已做全页兜底抓取；看运行日志「礼物线索」行定位。
下播后数据还在下播自动清零，开播重新记录。
打开直播间弹两个窗口只开一个，重复点聚焦已开窗口。
多账号并发每个账号独立推流隧道/端口/会话，可 4 账号并行（注意上行带宽：4×2500kbps≈10Mbps，建议上行 ≥15Mbps）。

十、运行日志与诊断

  • 菜单/界面可打开「运行日志」查看推流、监控、风险日志；
  • 诊断文件（本机调试用，位于软件数据目录 AppData\Roaming\TikTok直播工作台\ 下）：_risk_alerts.txt（风险告警）、_poll_diag.txt（监控轮询）、_diag_chatitems.txt（互动明细）、_ffmpeg_stderr.txt（推流 FFmpeg 报错）。导出诊断包时自动附带最近记录。
